The Interval: Paths You Can Run

Cubical's one move: stop treating a path as an opaque proof, and make it a function out of a line. Everything that was stuck starts computing — starting with funext, which becomes a one-liner.

The win for this lesson You can say what the interval I is, read λ i → … as a path, and follow the single most satisfying definition in this course: funext, proved in one line that computes. The axiom from Lesson 9 becomes a program.

The redesign: a path is a function from a line

Lesson 9 ended with the diagnosis: axioms jam because a book-HoTT path is a black box — there is nothing inside it for evaluation to act on. Cubical opens the box. Introduce a primitive interval:

I    a formal line segment          i0 ●─────────────● i1
     with two endpoints i0, i1      and points i "in between" — formal, not numbers

and define: a path in A is a function I → A. Writing p i for the point of A at position i:

p : a = b       means        p : I → A     with   p i0 ≡ a    and    p i1 ≡ b
                                                   (endpoints hold JUDGMENTALLY)

refl        = λ i → a                -- the constant function: stay at a
ap f p      = λ i → f (p i)          -- push the path through f. A DEFINITION now.
sym p       = λ i → p (1 - i)        -- run the line backwards

Two things just happened. First, a path has contents: it is a lambda, and lambdas compute. Second, operations that needed J (ap, sym) became one-line function manipulations. (I is a primitive, not an ordinary type — you cannot pattern-match on it or ask i = i0; you can only apply paths to it and abstract over it. That discipline is what keeps endpoints straight.)

The showcase: funext in one line

Lesson 9's unprovable principle. Watch:

given    h : (x : A) → f x = g x          -- pointwise: for each x, a path h x : I → B

wanted   f = g                            -- one path between the functions

funext h = λ i → λ x → h x i              -- DONE. and it computes.

Read it slowly, because it is almost embarrassing: for each position i on the line, produce the function λ x → h x i — "every point's own path, sampled at time i." At i0 that is λ x → f x, at i1 it is λ x → g x. The endpoints check judgmentally. The unprovable axiom was a swap of two lambda arguments, once paths became functions.

the picture: a path of functions IS a function into paths

     f x₁ ────────── g x₁        each row: one point's path  h x
     f x₂ ────────── g x₂        the whole square, read column-by-column:
     f x₃ ────────── g x₃        at each time i, a full function  λx. h x i
      │                │
     i0    time i →   i1         funext = read the rows as columns

Squares: higher paths get contents too

A path between paths is a function of two interval variables — literally a square. The tower from Lesson 1 becomes concrete geometry: n-dimensional paths are functions Iⁿ → A, i.e. n-cubes. That is where the name "cubical" comes from.

q : p₁ = p₂     (paths between paths)         a ── p₁ ── b
q : I → I → A                                 │           │      a square:
q i j,  with the four edges fixed             │     q     │      2 interval variables
                                              a ── p₂ ── b

What is NOT solved yet (the honest IOU)

The interval alone gives you paths you can write and apply. Two powers are still missing, and they are exactly next lesson's subject:

  • transport — given p : A = B, actually carrying an A to a B. Being a function I → Type does not by itself say how to move along it.
  • ua — manufacturing a universe path from an equivalence. λ i → ? — what type do you even write in the middle, between Bool and Binary? That needs a new type former (Glue).

So: funext is fully earned as of this lesson; univalence and a computing transport are earned next.

Check yourself

Answer from memory first. The click gives immediate feedback.

In cubical type theory, what is a path p : a = b?

A path is p : I → A with p i0 ≡ a and p i1 ≡ b holding judgmentally. Because it is a lambda, it has contents that evaluation can act on — that is the whole redesign.

Why does funext h = λ i → λ x → h x i actually work?

At i0 the body is λ x → h x i0 ≡ λ x → f x ≡ f, and likewise g at i1. The endpoint conditions hold by computation, so the lambda IS a path from f to g — a definition, not an axiom.

Say it in your own words

Explain cubical's core move and why it makes funext trivial. Three sentences.

Cubical replaces the opaque identity type with paths that are literally functions out of a primitive interval I, with the endpoint conditions holding judgmentally — so a path is a lambda, and lambdas compute. Given pointwise paths h x : f x = g x, the term λ i → λ x → h x i samples every point's path at time i, and at the endpoints it is judgmentally f and g — so it simply is a path f = g. What was an unprovable axiom in book-HoTT becomes an argument swap, and it reduces like any program.
