Univalence

The one axiom the course was built toward: identity of types is equivalence of types. Everything you have learned — paths, transport, the propositional ≃ — was assembling the pieces of this sentence.

The win for this lesson You can state univalence precisely, say why it is an axiom in book-HoTT and what it computes to, and name what it buys. Thanks to the earlier lessons, this is a consolidation, not a new mountain.

The statement

There is always a canonical map from a path to an equivalence, definable by path induction (J): send refl to the identity equivalence.

idtoequiv : (A = B) -> (A ≃ B)      -- from J:  idtoequiv refl = id-equiv
                                    -- "a path already contains a dictionary"

Univalence is the axiom that this map is an equivalence. Equivalently:

(A =_𝒰 B)  ≃  (A ≃ B)               -- identity of types IS equivalence of types

ua : (A ≃ B) -> (A = B)             -- the inverse direction: the NEW content
                                    -- turn an equivalence into a path

The easy direction (idtoequiv) was always there — a path lets you transport, which gives an equivalence. The content of univalence is the reverse: ua manufactures a path out of any equivalence, and univalence promises the two directions are inverse. That is the precise form of "the path is the dictionary" from Lesson 2. 

              idtoequiv  (free, from J)
   A = B   ─────────────────────────▶   A ≃ B
   (path)  ◀─────────────────────────   (dictionary)
              ua  (the axiom)

   univalence = "these two arrows are inverse"  — round trips are the identity

What it computes to (the usable content)

The reason univalence is worth anything is its computation rule: transporting along a ua-path just runs the equivalence.

transport (λ X -> X) (ua e)  =  e        -- the ua-β rule: "the dictionary, executed"

-- e.g.  transport (λ X -> X) (ua not) true  =  false
--       transport GroupStr (ua e) : GroupStr Bool -> GroupStr Binary   (the Lesson 2 swap)

So a path in the universe stores exactly an equivalence, and transport reads it. This is the machinery behind the Bool/Binary payoff: prove a property once, transport it across ua e for free.

Why it is an axiom in book-HoTT (and why cubical exists)

idtoequiv is definable, but the claim "idtoequiv is an equivalence" is independent of bare type theory — you can neither prove nor refute it (this is exactly the Binary = Bool independence from Lesson 2). So book-HoTT postulates it. And a postulate has no computation rule:

The catch, and the fix As an axiom, ua does not compute: transport (λ X.X) (ua e) true typechecks but gets stuck (canonicity breaks — the Lesson 4 checkable-vs-computable split). Cubical type theory makes univalence a theorem that runs, by building paths from the interval so that ua has real reduction rules. That is the entire reason cubical exists, and the destination of this course (Lessons 10–11).

What univalence buys

ConsequenceWhat it says
The universe is a groupoidA =𝒰 A has one proof per self-equivalence of A, so the universe is not a set — it has real path structure (Bool = Bool has refl and ua not).
Transport across equivalences (SIP)Prove a property or a whole structure for one type, get it for any equivalent type — the structure identity principle. The Lesson 2 payoff, now justified.
Function extensionalityUnivalence implies funext (equal-if-pointwise-equal). One axiom subsumes the other (Lesson 4's owed extensionality).
Equivalence inductionTo prove a claim for all equivalences e : A ≃ B, prove it for id — because Σ(B). A ≃ B is contractible. The analog of J, for equivalences.
Why the careful ≃ was necessary. Univalence pairs A = B with A ≃ B, so the two must match structurally. That is exactly why Lesson 6 insisted "is an equivalence" be a proposition: with the naive isIso, A ≅ B carries spurious baggage A = B cannot hold, and the two sides would not match. See Recursion, Induction & Uniqueness for the full argument.

Check yourself

Answer from memory first. The click gives immediate feedback.

What does univalence assert about idtoequiv : (A = B) → (A ≃ B)?

idtoequiv is always definable (from J). Univalence is the assertion that this canonical map is an equivalence, so (A = B) ≃ (A ≃ B). Its inverse is ua.

Why is univalence an axiom in book-HoTT rather than a theorem?

In bare type theory you can neither prove nor refute that idtoequiv is an equivalence (same independence as Binary = Bool), so it is postulated. As an axiom it does not compute; cubical makes it a computing theorem.

Say it in your own words

State univalence, say why it is an axiom in book-HoTT, and name one thing it lets you do. Three sentences.

Univalence says the canonical map idtoequiv : (A = B) → (A ≃ B) is an equivalence, so identity of types and equivalence of types coincide, and its inverse ua turns an equivalence into a path with transport (λX.X) (ua e) = e. It is an axiom in book-HoTT because idtoequiv is definable but "it is an equivalence" is independent of bare type theory, and as an axiom it does not compute — cubical makes it a theorem that runs. It lets you transport any structure and its proofs across an equivalence for free, makes the universe a groupoid, and implies function extensionality.
