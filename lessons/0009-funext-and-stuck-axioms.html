Funext, and Why Axioms Don't Compute

A short lesson with one job: put your finger on a concrete term that typechecks and then jams. This is the problem the rest of the course solves.

The win for this lesson You can state function extensionality, say why bare type theory can neither prove nor refute it, and point at the exact spot where an axiom-built term stops reducing. After this, "cubical makes it compute" stops being a slogan.

Two functions that are obviously equal — and unprovably so

double n = n + n
twice  n = 2 * n

h : (n : ℕ) → double n = twice n     -- provable, by induction. they agree EVERYWHERE.

double = twice                        -- can you conclude THIS?

Function extensionality (funext) is the principle that closes that gap: if f x = g x for every x, then f = g. And in bare intensional type theory it is not provable — and, per the pattern you know from Lesson 2, not refutable either. It is independent: the bare rules compare functions by their definitions, stay silent about pointwise agreement, and leave the question open. (Same status Binary = Bool had.)

Book-HoTT closes the gap in one of two ways, and both are the same move at bottom:

  • postulate funext as an axiom, or
  • postulate univalence, which implies funext.

The price tag: an axiom is a constant with no reduction rule

Recall the two promises from Lesson 4: checkable (the typechecker accepts it) and computable (a closed term reduces to a value). Axioms keep the first and break the second. Here is the jam, concretely:

p = ua not : Bool = Bool              -- a path built from the axiom

b = transport (λ X → X) p true        -- typechecks fine.  b : Bool.

evaluate b:
   transport (λ X → X) (ua not) true
   = transport (λ X → X) (ua not) true     -- ...nothing fires. `ua` is a postulate:
   = transport (λ X → X) (ua not) true     -- no rule rewrites it. evaluation HALTS HERE.

b is a closed term of type Bool that is neither true nor false.   ← canonicity broken

The same jam happens with funext: a proof built by transporting along funext h typechecks, but never reduces to refl-shaped evidence — it stays wrapped around the opaque constant. Canonicity — "every closed Bool is true or false, every closed ℕ is a numeral" — fails the moment one axiom enters a term.

Why this matters beyond aesthetics Every payoff this course promised runs through transport along ua- or funext-paths: the Bool/Binary swap, the ℚ quotient and the loop proof. In book-HoTT all of it typechecks and then jams. You can reason on paper; you cannot press run. The fix is not another axiom — it is a redesign of what a path is, so that ua and funext become definable terms with reduction rules. That redesign is the next lesson.

Exactly why does transport (λX. X) (ua not) true get stuck in book-HoTT?

The term typechecks — that is the point. But evaluation must rewrite ua not to proceed, and a postulated constant has no computation rule. The closed Bool term is neither true nor false: canonicity is broken.

Say it in your own words

Explain to a colleague what funext says, why book-HoTT has to postulate it, and what goes wrong when it is a postulate. Three sentences.

Funext says two functions that agree at every input are equal, and bare intensional type theory can neither prove nor refute this — it is independent, so book-HoTT postulates it (or postulates univalence, which implies it). A postulate is a constant with no reduction rule, so any term built from it typechecks but jams during evaluation: transport (λX.X) (ua not) true is a closed Bool that is neither true nor false, which is a failure of canonicity. That means every transport-across-equivalence payoff works on paper but does not run, and fixing it requires redefining what a path is rather than adding more axioms.
