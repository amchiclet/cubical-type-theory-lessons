Higher Inductive Types

Ordinary inductive types declare points. Higher inductive types also declare paths. That one extension pays off the oldest IOU in this course — quotients without setoid hell — and hands us the first type whose path structure is genuinely non-trivial.

The win for this lesson You can say what a path constructor is (and what it is not), define a function out of a HIT by handling every constructor, and follow a real proof that the circle's loop is a different path from refl — the first theorem that a type has a hole.

Why you'd want this (the motivation first)

Two itches, both familiar:

  • Quotients. Lesson 2 promised "quotients without setoid hell": rationals, multisets, syntax modulo renaming — types where some elements should be equal but ordinary inductive types give you no way to say so. You end up carrying an equivalence relation everywhere and re-proving that every function respects it.
  • Real path structure. The tower from Lesson 1 and the groupoid universe from Lesson 7 say types can have non-trivial paths. But every type you can build so far (Bool, ℕ, pairs, functions) is a set. Where do the interesting spaces actually come from?

One answer to both: let a type's definition declare paths, not just points. Want two elements identified? Declare a path between them (quotients). Want a hole? Declare a loop (spaces).

The smallest example: the circle

data S¹ : Type where
  base : S¹                 -- a point constructor
  loop : base = base        -- a PATH constructor

        ┌────────┐
        │  loop  ▼
        ●  base            one point, one declared self-path
        ▲────────┘

Defining a HIT asks you to prove nothing — like any inductive type, you just list constructors, and the type is freely generated by them. The groupoid algebra (loop ∙ loop, sym loop, refl) comes for free from the identity type, so base = base now contains …, sym loop, refl, loop, loop ∙ loop, …

What a path constructor is NOT loop is a constructor of S¹ whose type happens to be an identity type. It is not a new constructor of the identity type — that still has exactly one, refl (Lesson 5). Compare: length xs : ℕ produces a natural number without being a constructor of ℕ. Which inhabitants an identity type ends up with depends on the type's own definition: for Bool you declared no paths, so its identity types are trivial; for S¹ you declared loop, so base = base is rich. Nothing injects from outside; S¹'s own signature put the path there.

Using a HIT: one obligation per constructor

To define f : S¹ → X, handle every constructor — and for a path constructor, you owe a path:

S¹-rec : (x : X) → (ℓ : x = x) → (S¹ → X)
   base ↦ x           -- a point of X
   loop ↦ ℓ           -- a path x = x in X   ("where does the loop go?")

-- e.g. the map that winds twice:   base ↦ base,  loop ↦ loop ∙ loop

This is the same "one case per constructor" rule as ever — the new part is just that a path constructor's case is a path. Note the division of labour: S¹-recursion eliminates the HIT (cases for base and loop); J and its tools eliminate paths (transport, ap apply to loop like any path). Two different eliminators, and the proof below uses both.

The theorem: loop ≠ refl (the circle has a hole)

Both loop and refl inhabit base = base. Are they the same path? If they were, the circle would be a point. Here is the proof they are not — watch the two eliminators cooperate:

-- 1. Build a family over S¹ by S¹-RECURSION (into the universe):
Cover : S¹ → Type
Cover base = ℤ                    -- the fibre over base is the integers
Cover loop = ua succ              -- loop must go to a PATH ℤ = ℤ in the universe;
                                  -- univalence manufactures it from succ : ℤ ≃ ℤ

-- 2. Read the path with J's tool, TRANSPORT (+ the ua-β rule from Lesson 7):
transport Cover loop = succ       -- transporting along loop is "+1"
transport Cover refl = id         -- transporting along refl does nothing

-- 3. Suppose loop = refl. Transport respects equal paths, so:
succ = id  :  ℤ → ℤ
succ 0 = id 0   ⟹   1 = 0        -- contradiction in ℤ.

∴  loop ≠ refl
the picture:  Cover wraps a line of integers around the circle

   fibre ℤ:   … -1   0   1   2 …          going around loop once
                   \  |  /                 climbs one step:  n ↦ n+1
                    (base)                 refl stays put:   n ↦ n
                  ●──loop─↺

Notice what each piece did: S¹-recursion built Cover (a case for each constructor), univalence turned the successor equivalence into the path that loop maps to, and transport read the two paths back as different functions. The circle's non-trivial structure was declared in one line and detected by transport. (The stretch version of this argument computes the whole path space: (base = base) ≃ ℤ — every loop is a winding number. Ask if you want it walked through.)

The practical face: quotients (fractions, and what setoid hell actually is)

The same mechanism — declare a path — is how you build quotients. The best example is one you have known since school: fractions. 1/2 and 2/4 should be equal, but as pairs (1,2) and (2,4) they are different data.

The world without paths: setoid hell, spelled out

Without HITs you keep the raw pairs and carry the "real" equality as a side relation:

Frac = ℤ × ℤ⁺              a/b ~ c/d   iff   a·d = c·b

The theme of what follows: ~ is a second-class equality, and everything that is free for = becomes manual labour for ~.

CostWhat it looks like
A congruence proof per operationadd, mul, neg, inv, … each owes a lemma a ~ a' → b ~ b' → add a b ~ add a' b'. N operations, N hand proofs, forever.
The =-toolkit doesn't applytransport, ap, J — the free-substitution engine of Lesson 2 and Lesson 5 — work on =, not on your bespoke ~. With real equality, P(1/2) → P(2/4) is free for every P; with ~ you transfer one manually-proven property at a time. Setoid hell is living without transport for your intended equality.
It infects every type formerA list of fractions needs a lifted List-~; pairs need a pair relation; setoid-functions must bundle a respects-proof. The relation is dragged through every container and interface.
Abstraction breaks silentlynumerator (a, b) = a typechecks fine — yet numerator(1/2) = 1 and numerator(2/4) = 2, so it distinguishes "equal" values. Nothing stops you; the discipline is by convention only.

The HIT: promote ~ to a genuine =

data ℚ : Type where
  _/_    : ℤ → ℤ⁺ → ℚ
  scale  : (a : ℤ)(b : ℤ⁺)(k : ℤ⁺) → a / b = (k·a) / (k·b)    -- 1/2 = 2/4, by decree

Now 1/2 = 2/4 is a real path, so the whole =-toolkit applies: transport carries any property across for free, no congruence lemmas, no lifted relations, no conventions. The cost concentrates in exactly one place — a function out of ℚ owes a case for scale, a proof that it respects the identification. And look what that buys:

The typechecker now enforces well-definedness Try to define numerator : ℚ → ℤ. You owe the scale case: a proof that numerator(1/2) = numerator(2/4), i.e. 1 = 2. There isn't one — so numerator is unwritable. The ill-defined function that the setoid world accepted silently is rejected by the machine. The per-path obligation is not bookkeeping; it is well-definedness, enforced.

Other quotients follow the same recipe (integers as differences a ⊝ b, multisets, syntax modulo renaming). The code-level walkthrough is in HIT Paths in Code.

The honest catch, one more time. In book-HoTT, HITs and ua are axiomatic, so transport Cover loop is stuck — the proof above typechecks but nothing runs. In cubical, paths are real functions out of the interval and all of this computes. That is the destination of the next lessons.

Answer from memory first. The click gives immediate feedback.

What exactly is loop?

The identity type's only constructor is still refl. loop is declared in S¹'s own signature; it is a new inhabitant of base = base, not a new constructor of = — and provably not refl.

In the proof of loop ≠ refl, what does transport Cover do with the two paths?

transport Cover loop = succ (by ua-β) while transport Cover refl = id. If the paths were equal the functions would be too, giving 1 = 0. Different behaviours under transport ⟹ different paths.

Say it in your own words

Explain to a colleague what a higher inductive type adds to ordinary inductive types, and how one proves the circle's loop is not trivial. Three sentences.

A higher inductive type lets a definition declare path constructors alongside point constructors, so you can build types where chosen elements are identified (quotients) or where a self-path is a genuine loop (the circle) — and eliminating out of it costs one case per constructor, a path for a path. The identity type itself is unchanged: refl is still its only constructor; loop is a constructor of S¹ that happens to inhabit base = base. To show loop ≠ refl, build a family Cover over the circle sending loop to ua succ; transport reads loop as successor and refl as identity, so equality of the paths would force 1 = 0.
